# Douyin Assistant – Repository Health Audit

_Completed: 2024-10-22_

## 1. Repository Overview
- **Primary language:** Python 3.11 (per `.python-version` and `pyproject.toml`).
- **Packaging:** Lightweight `pyproject.toml` with a minimal dependency list, duplicate `requirements.txt`, and a checked-in `uv.lock` generated by the `uv` package manager. No build system configuration is defined in `pyproject.toml`.
- **Runtime entrypoints:**
  - `main.py`/`src/main.py` – rich-powered CLI for account management, download, and upload tasks.
  - `gui_main_ctk.py`/`src/main_window_ctk.py` – CustomTkinter desktop UI using the `WorkerCTK` orchestration layer.
  - Playwright-powered automation flows in `src/uploader.py`, `src/account_manager.py`, and `src/worker_ctk.py`.
- **Build/CI:** GitHub Action (`.github/workflows/build.yml`) builds PyInstaller artifacts on macOS & Windows when tags are pushed. No linting, tests, or security checks are executed in CI.

## 3. Key Findings (Severity-Sorted)

### Critical
1. **Corrupt video processing & crash for mid-sized files**  
   - **Location:** `src/video_processor.py`, `_simulate_frame_deletion` (lines 64-105).  
   - **Problem:** The "frame deletion" feature performs random block skipping on the raw binary file. For typical MP4 sizes (e.g., ~150 KB), the `random.randint(10, total_blocks - 10)` call raises `ValueError: empty range in randrange(10, 9)` and aborts the upload pipeline. When it does not crash, it writes truncated byte streams that produce corrupted video files.  
   - **Reproduction:**  
     ```bash
     python - <<'PY'
     from src.video_processor import VideoProcessor
     from pathlib import Path
     path = Path('medium.mp4')
     path.write_bytes(b'0' * (8192 * 18))
     try:
         VideoProcessor.process_video(str(path), delete_ratio=0.3)
     except Exception as e:
         print(type(e).__name__, e)
     finally:
         path.unlink()
     PY
     # => ValueError: empty range in randrange(10, 9)
     ```
   - **Impact:** Batch/automated uploads fail for common file sizes; successful runs risk producing unusable, corrupted media uploads.  
   - **Recommendation:** Replace the fake "frame deletion" logic with either (a) a real video-processing backend (ffmpeg/pyAV) or (b) disable the feature until a safe implementation exists. Add deterministic unit tests around the processing pipeline.

2. **Batch uploads always treated as failure, causing duplicate uploads**  
   - **Location:** `src/worker_ctk.py` – `run_batch_upload` (lines 351-444) vs `run_single_upload` (lines 292-349).  
   - **Problem:** `run_single_upload` never returns a boolean; it performs the upload and logs success but implicitly returns `None`. `run_batch_upload` interprets `result = self.run_single_upload(...)` as falsy, increments `failed_count`, and keeps trying the next account for the same video. This leads to inaccurate status reports and repeated uploads to every selected account even after success.  
   - **Impact:** Users see "failed" statuses, duplicated uploads, and incorrect success metrics, undermining trust in automation.  
   - **Recommendation:** Make `run_single_upload` return the boolean from `Uploader.upload_video` and adjust `run_batch_upload` to respect it (stop iterating accounts once a video succeeds, increment correct counters, hook into callbacks cleanly).

### High
3. **Playwright upload loop can hang indefinitely**  
   - **Location:** `src/uploader.py`, `upload_single_video` (lines 544-566).  
   - **Problem:** After selecting a file, the code spins in `while True` waiting for an element matching `'重新上传'`. If Douyin’s UI changes or the selector fails, the loop never exits and the process hangs. No timeout or failure path exists.  
   - **Impact:** Automation jobs can stall forever, blocking further uploads or requiring manual intervention.  
   - **Recommendation:** Introduce explicit timeouts (`page.wait_for_selector(..., timeout=...)`), guard with a maximum retry duration, and surface actionable errors.

4. **Cookie validation overly lax for Playwright login path**  
   - **Location:** `src/account_manager.py`, `update_cookie_with_playwright` (lines 521-568).  
   - **Problem:** Unlike the browser-cookie path (which requires `sessionid`), the Playwright login path only checks `len(cookie_str) > 10` before persisting the cookie. Partial or invalid cookies are therefore treated as valid and saved.  
   - **Impact:** Subsequent download/upload actions fail mysteriously when concealed invalid cookies are used.  
   - **Recommendation:** Enforce the presence of required keys (e.g., `sessionid`) and surface a clear error when authentication cookies are incomplete.

5. **CI/CD provides binaries without any regression signal**  
   - **Location:** `.github/workflows/build.yml`.  
   - **Problem:** The workflow only builds PyInstaller executables on tag pushes; there are no lint, type, security, or test stages. Releases can ship with syntax errors, automation regressions, or vulnerable dependencies unspotted.  
   - **Impact:** Users may receive broken or insecure binaries.  
   - **Recommendation:** Extend the workflow (or add a separate one) to run `ruff`, `mypy`, a smoke-test suite, and `pip-audit` on pull requests and main branch pushes before packaging.

### Medium
6. **Extremely large, monolithic GUI module** (`src/main_window_ctk.py`, 1312 LOC) hampers maintainability, testing, and comprehension. Breaking it into cohesive components (layout, bindings, data adapters) would reduce complexity and unblock UI-level tests.

7. **Fallback stub classes in `WorkerCTK` mask import errors** (lines 18-47). If optional imports fail, the code silently replaces them with no-op classes, leading to runtime failures later without obvious cause. Prefer failing fast, or explicitly mock dependencies in tests instead of production fallback stubs.

8. **Hard-coded subprocess invocations** (`AccountManager` & `Uploader` install helpers) rely on `pip`/`python` being in `PATH`, which breaks on isolated installs and complicates security reviews. Use `sys.executable -m pip` and surface errors clearly.

9. **Numerous style & type issues** hinder readability and tooling adoption (see §4). Inline semicolons, ambiguous single-letter variables, and missing type annotations should be addressed before enabling stricter tooling.

### Low
10. **Invalid escape sequence warnings** (`src/uploader.py`, lines 255-432) should be fixed with raw strings or doubled backslashes to avoid platform-dependent bugs when new Python versions tighten warnings.

11. **CLI feature gap** – the CLI only exposes `post`, `favorite`, `collection`, while GUI supports additional download modes (`like`, `collects`, `mix`, `music`, `live`, `one`). Documented feature parity is inconsistent.

12. **Auto-created `accounts.json`** isn’t accompanied by migration/versioning logic; consider validating schema and documenting default structure.

## 4. Static Analysis Detail
- **Ruff (88 errors):** Predominantly structural hygiene issues – multi-statements per line, ambiguous variable names, misuse of f-strings, and excessive inline statements. Enabling Ruff with auto-fix would resolve most of these automatically.
- **Mypy (51 errors):**
  - Incorrect type annotations: `self.browser` is annotated as `Browser` but `launch_persistent_context` returns `BrowserContext`.
  - Functions define `list[...]` parameters with `None` defaults (implicit Optional) – flagged under default strictness.
  - Numerous attributes are set dynamically (`AccountManager._config_found`) leading to “attribute not defined” diagnostics.
  - Missing type information for third-party packages without `.pyi` stubs.
- **Radon complexity:** `Uploader.start_session` scored **D (26)**, and several install helpers in `AccountManager` are **C** or **B**. Refactoring into smaller helpers and extracting shared logic would reduce risk.
- **Raw metrics:** `account_manager.py` (694 LOC) and `main_window_ctk.py` (1312 LOC) dominate the codebase and will benefit from decomposition.

## 5. Dependency & Security Notes
- `pip-audit` detected **pip 24.0** vulnerability (**GHSA-4xh5-x5gv-qwph**). Upgrade the virtual environment bootstrapper to `pip>=24.0.1` (or rely on `uv` everywhere).
- Dependencies are effectively unpinned (except `customtkinter>=5.2.2`), increasing reproducibility risk. Consider pinning runtime dependencies in `pyproject.toml` and generating `requirements.lock` via `uv pip compile` or `pip-tools` for releases.

## 6. Testing & QA Status
- **Automated tests:** None found (`tests/` absent). No unit/integration coverage for downloader, uploader, or GUI orchestration logic.
- **Recommendation:**
  - Introduce `pytest` with fixtures that abstract network and Playwright interactions.
  - Start with pure-Python units: `VideoProcessor`, CLI argument handling, config discovery, downloader URL parsing.
  - Add smoke tests for Playwright flows using `pytest` markers and either headless mode or Playwright’s testing library.

## 7. Runtime Observations
- CLI works for help/list commands and automatically bootstraps `accounts.json` when missing.
- GUI launcher fails in the default Linux container because `tkinter` is not installed system-wide. Document platform prerequisites (e.g., Ubuntu: `sudo apt-get install python3-tk`) or provide a guard that surfaces a friendlier error message.

## 9. Suggested Engineering Improvements
- **Shared Playwright installer:** Factor common installation logic between `AccountManager` and `Uploader` into a dedicated utility to eliminate duplication and ensure consistent error handling.
- **Config-driven selectors:** Store Playwright selectors in a dedicated module or JSON to ease maintenance when Douyin UI changes.
- **Logging discipline:** Replace `print` calls with the existing `rich` console logger or Python’s `logging` module for consistent verbosity control.
- **Packaging strategy:** Decide between `uv` and `pip`; keep a single source of truth for dependency management to avoid drift between `requirements.txt` and `pyproject.toml`.
- **Module decomposition:** Break up large modules (`main_window_ctk.py`, `account_manager.py`) into submodules (UI layout, installation helpers, cookie management) to enable targeted tests and reduce cognitive load.
